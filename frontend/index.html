IRIS • Database Systems Review 1 Cheatsheet

Key architectural arguments and speaking points for your faculty presentation

1. Problem Statement & Motivation

Modern engineering teams repeatedly face similar production outages and database anomalies. Existing bug trackers (like Jira) only act as dumb text logs with no intelligence, while generic ChatGPT lacks internal company infrastructure history.

IRIS Innovation: Relational Database is the centerpiece. AI is grounded directly in relational historical records via SQL JOIN queries.

2. Relational Schema Architecture

  • • users: id, username, full_name, role, created_at
  • • problems: id (PK), title, description, category, severity, keywords, reported_by, status, created_at, resolved_at
  • • solutions: id (PK), problem_id (FK), solution_text, source, resolved_by, confidence_score, root_cause, action_steps
  • • sql_query_logs: id, query_type, query_text, params, rows_affected, execution_time_ms, timestamp (IST)

3. AI Engine Architecture (Zero Hardcoding)

Powered by Google Gemini 3.8 Flash through Database-Augmented Generation (DAG). The engine retrieves historical records via parameterized SQL, injects organizational precedents into the prompt context, and synthesizes root causes with citations.

4. Closed-Loop Learning

When an engineer accepts a solution, it executes an INSERT INTO solutions and updates the problem status to 'RESOLVED'. This closed loop ensures every newly solved problem immediately becomes historical knowledge for future team members.
